# ADR 0010: 룸 측정을 REW 측정 파일과 Dirac Live 프로젝트에서 읽는다

- **상태:** 결정됨 (2026-11-03)
- **결정자:** 유지보수자 (115dkk)
- **선행:** ADR 0004(룸 보정 v2), ADR 0005(가상 룸 튜닝), ADR 0008(가상 룸 튜닝 v2)

## 맥락

Impulcifer의 룸 보정과 가상 룸 튜닝은 측정 폴더의 `room-<스피커>[-left|-right].wav`를 읽는다. 이 파일은 Impulcifer의 스윕을 측정 마이크로 녹음한 것이고, 서비스가 스윕을 역컨볼루션해 임펄스 응답을 얻는다.

유지보수자가 쓰는 측정 환경에서는 다채널 스윕을 Impulcifer가 아니라 AV 리시버의 Dirac Live가 낸다. Dirac Live는 리시버에 붙어 있어 채널이 많아도 스피커를 하나씩 울릴 수 있고, macOS의 HDMI 8채널 한계도 거치지 않는다. 이때 측정 마이크(Umik-1)의 응답은 Dirac Live 프로젝트(`.liveproject`)에 남는다. 두 귀의 녹음은 다른 노트북의 Audacity로 따로 하고, 이것은 지금처럼 Impulcifer의 녹음 입력으로 쓴다. 룸 측정을 REW로 하는 사용자도 많다. REW는 측정을 `.mdat`에 저장한다.

두 파일에는 이미 임펄스 응답이 들어 있다. 유지보수자는 합성 화면이 기존 녹음과 CSV에 더해 이 두 파일을 입력으로 받게 하자고 했다. REW는 형식이 공개돼 있을 테니 그것을 따르고, `.liveproject`는 파일을 분석해 측정값을 찾으라고 했다.

## 결정

1. **두 파일은 룸 측정의 다른 출처다.** 새 설정 `room_measurement_file`에 `.mdat`이나 `.liveproject`를 주면, 그 파일의 임펄스 응답을 폴더의 `room-*.wav` 대신 룸 측정으로 쓴다. 이미 임펄스 응답이므로 스윕 역컨볼루션을 하지 않는다. 범용 룸 측정(`room.wav`), 룸 목표, 바이노럴 녹음은 지금처럼 폴더에서 읽는다. 룸 측정이 쓰이는 단계(룸 EQ, 가상 룸 튜닝 v1·v2)의 계산은 바뀌지 않는다.
2. **형식은 공개 명세와 파일 자체에서 정한다.** REW의 `.mdat`은 Java 객체 직렬화 스트림이다(Oracle, Java Object Serialization Specification 6장). 스트림이 클래스 이름과 필드 이름을 담고 있으므로 REW 프로그램을 보지 않고 읽을 수 있다. Dirac Live 프로젝트는 Qt `QDataStream` 머리말 뒤에 측정 블록이 protobuf 와이어 형식으로 들어 있다. 둘 다 공개된 인코딩이다. 필드의 뜻은 유지보수자 자신의 프로젝트 11개와, REW 5.40 beta 135를 일반 사용자로 돌려 만든 파일로 확인했다. REW와 Dirac 프로그램을 디컴파일하거나 실행 중에 후킹하지 않았다. 유지보수자가 받은 Dirac 분석 자료(디컴파일 결과와 후킹 스크립트)는 구현에 쓰지 않으며 저장소에 넣지 않는다. REW의 EULA는 프로그램의 역설계를 막지만, 사용자가 저장한 데이터 파일을 읽는 것은 다루지 않는다.
3. **Dirac 프로젝트의 측정 블록만 읽는다.** 측정 블록 뒤에는 바이트 엔트로피가 8.0인 블록(필터 설계로 보임)이 오는데, 압축이나 암호화를 풀려고 하지 않는다. 측정 블록의 응답 행렬은 행이 측정 위치, 열이 스피커인 행 우선 배열이고, 원소는 μ-law로 압신한 16비트 정수(빅 엔디언)와 배율 하나다. μ 값은 파일에 없어서 통계로 정했다. 위치 1의 주 스피커와 서브우퍼 응답에 μ = 0, 15, 63, 255, 1023, 4095, 16383, 65535를 넣어 보니, μ = 255에서 피크 앞 잡음의 첨도가 가우스 잡음의 값인 3에 가장 가깝고(서브 2.95, 그 이웃 2.49와 3.58), 감쇠 곡선의 직선 맞춤 잔차가 가장 작았다(0.23 dB). 선형으로 읽으면 잡음 바닥이 피크보다 36 dB(서브는 15 dB)밖에 낮지 않아 Umik-1 측정으로 볼 수 없다. μ = 255는 G.711의 값이다.
4. **측정을 스피커와 귀 위치에 대응시킨다.** 룸 측정은 스피커마다 왼쪽 귀 위치와 오른쪽 귀 위치의 응답 하나씩이다. 대응은 `room_measurement_map`에 `FL.left=<id>,FL.right=<id>` 꼴로 적고(`FL=<id>`는 두 귀 위치에 같은 측정), 비우면 자동으로 정한다. 자동 규칙은 `docs/rust/EXTERNAL_MEASUREMENTS.md`에 있다. REW는 측정 이름에서 스피커와 귀를 읽고, 귀가 없으면 두 귀 위치에 같은 측정을 쓴다. Dirac은 스피커 이름에서 슬롯을 읽고, 두 귀 위치에 위치 1(Dirac의 주 청취 위치)을 쓴다. 화면은 파일을 분석해 자동 대응을 보여 주고 사용자가 고치게 하며, 작업에는 화면에 보이는 대응을 그대로 보낸다.
5. **서브우퍼 측정은 쓰지 않는다.** Impulcifer에는 서브우퍼 슬롯이 없고, 저역은 가상 베이스(ADR 0006)가 만든다. Dirac의 스피커 종류 4(상한 200 Hz)와 이름이 sub·subwoofer·LFE인 측정은 대응하지 않고 목록에만 보인다.
6. **마이크 보정은 명시한 파일, 폴더 파일, 프로젝트에 든 보정의 순서로 쓴다.** Dirac 프로젝트는 측정 마이크의 보정 곡선을 담고 있다(유지보수자의 파일에서는 Umik-1 90° 보정, 10 Hz −3.19 dB, 18 kHz −5.46 dB). 응답 행렬은 이 보정을 적용하기 전의 값이라고 본다. 이름이 원시 모형이고 보정 곡선을 측정과 함께 저장하기 때문이다. 이 가정이 틀리면 보정이 두 번 걸린다. 룸 보정이 다루는 저역에서 이 마이크의 보정은 2 dB 안이다. REW 측정에는 사용자가 주는 보정만 쓴다.
7. **가져온 측정은 서로 다른 녹음으로 본다.** 가상 룸 튜닝은 한 녹음 안의 스피커 쌍만 비교한다(시계가 같아야 하므로). REW는 측정마다 시간 기준이 다를 수 있고, Dirac 응답 행렬은 원소마다 피크 앞 길이가 12 000 샘플 근처로 맞춰져 있어 스피커 사이의 시간 관계를 보장하지 않는다. 그래서 쌍을 만들지 않는다.
8. **샘플레이트가 작업과 다르면 리샘플한다.** 한 파일 안의 측정은 같은 샘플레이트여야 한다.
9. **파일은 믿지 않는 입력으로 읽는다.** 파서는 구조만 읽고 어떤 코드도 실행하지 않는다(Java 역직렬화가 아니다). 배열 길이는 남은 바이트로 제한하고, 중첩 깊이와 핸들 수에 상한을 두며, `unsafe`를 쓰지 않는다. 새 의존성은 없다.

## 결과

- Dirac Live로 스피커를 울린 측정과 REW로 잰 측정을 Impulcifer의 스윕으로 다시 재지 않고 룸 보정과 가상 룸 튜닝에 쓸 수 있다.
- Dirac 응답 행렬의 원소는 32 769 샘플(48 kHz에서 0.68초)이다. 룸 EQ v2가 측정의 잡음 바닥으로 부스트를 제한하는 검사는 1초 이상의 측정에서만 하므로, Dirac 측정에서는 이 검사를 건너뛰고 스피커와 귀 위치마다 경고를 남긴다. 부스트 상한(`room_max_boost`)과 기울기로 찾는 저역 롤오프는 그대로 적용된다.
- 폴더의 `room-*.wav`와 측정 파일을 함께 쓰지는 않는다. 측정 파일을 주면 폴더의 룸 측정은 읽지 않고 로그에 그 사실을 남긴다.
- 테스트 픽스처는 REW가 직접 저장한 파일(합성 임펄스 응답 둘과 주파수 응답만 있는 측정 하나)과, 관찰한 배치대로 테스트에서 만드는 Dirac 프로젝트다. 유지보수자의 Dirac 프로젝트와 다른 사람이 공유한 REW 파일은 저장소에 넣지 않고, 로컬 검증 결과만 PR에 적는다.
- 다시 제안하지 말 것: Dirac 필터 설계 블록을 풀어 읽는 것, Dirac이나 REW 프로그램의 동작을 디컴파일로 알아내는 것.
