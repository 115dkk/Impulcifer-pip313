# ADR 0020: 안드로이드 앱은 Tauri 셸에 새 화면을 얹고, 파일은 경로로 다룬다

- **상태:** 결정됨 (2026-11-15)
- **결정자:** 유지보수자 (115dkk)
- **관련:** ADR 0002(Rust 코어와 Tauri 셸), ADR 0003(3.x 화면과 오버레이 카탈로그), ADR 0012(저장소에 두는 서명 키). `CLAUDE.md`의 '안드로이드 이식 (3.x)'이 미뤄 둔 네 가지(화면을 띄우는 방식, 패키징, 배포, 업데이트)를 여기서 정한다.

## 맥락

유지보수자는 2026-11-15에 안드로이드 이식의 범위를 정했다. 3.x를 바탕으로 하고, 안드로이드에서 할 이유가 없는 녹음(측정)만 빼며, 나머지는 모두 옮긴다. 그중 처리(룸 보정, 헤드폰 보정을 비롯한 BRIR 생성)와 출력 복원이 핵심이다. 화면은 데스크톱 화면을 그대로 옮기지 않고 Studio를 토대로 작은 화면과 터치에 맞게 새로 만들며, Stable은 옮기지 않는다. 시스템 정보는 안드로이드의 사정에 맞게 보여야 한다. 화면을 무엇으로 만들지는 Slint와 Tauri 가운데 고르기로 했다.

3.21.2에서 확인한 사실은 이렇다.

- 녹음 백엔드를 뺀 `impulcifer-service`와 `impulcifer-cli`는 `aarch64-linux-android`로 빌드되고 CLI가 기기에서 돈다(PR #316).
- 3.x 화면은 Tauri 2 위의 바닐라 JS다. 서비스와는 `pywebview_api` 명령 하나로 말하고, IPC 표면은 `ipc.d.ts`가 타입으로 묶으며, 문자열은 아홉 언어 카탈로그에서 온다. 3.21.2부터 기능마다 이벤트 연결, 다시 그리기, 요청 필드를 자기 파일에 두고 `FEATURES` 표가 순서를 정한다.
- 순정 Tauri 2.11.5의 `tauri::mobile_entry_point`는 `#![forbid(unsafe_code)]` 아래에서 컴파일된다(`cargo check -p impulcifer-app --lib --target aarch64-linux-android`).
- Slint 1.18의 안드로이드 진입점은 앱 크레이트에 `#[unsafe(no_mangle)] fn android_main`을 직접 쓰게 하고, 기본 액티비티(`NativeActivity`)에는 Java 코드를 둘 자리가 없다.
- Tauri의 대화상자 플러그인은 안드로이드에서 폴더를 고르지 못하고, 파일은 경로가 아닌 `content://` 주소로 돌려준다. 서비스의 입력과 출력은 모두 파일 경로다.
- 안드로이드 17에서 앱은 `/storage`의 목록과 `/proc/sys/kernel/osrelease`를 읽지 못한다. 저장소 볼륨과 OS 판은 플랫폼 API로만 알 수 있다.
- 앱 프로세스에는 `TMPDIR`이 없어 Rust의 `temp_dir()`이 앱이 쓸 수 없는 `/data/local/tmp`를 가리킨다.

## 결정

1. **셸은 Tauri 2다.** `apps/impulcifer-app`을 라이브러리와 실행 파일로 나눈다. 셸은 `src/lib.rs`의 `run()`이고, 데스크톱 실행 파일(`src/main.rs`)은 그것을 부르며, 안드로이드는 같은 크레이트의 cdylib을 읽어 같은 함수로 들어간다. Slint를 고르지 않은 까닭은 넷이다. 화면의 규칙과 IPC 호출을 다른 언어로 한 벌 더 만들어 두 벌을 함께 고쳐 가야 한다. 진입점과 JNI 때문에 unsafe 허용치를 올려야 한다. 저장소 권한과 볼륨을 묻는 Kotlin 코드를 둘 자리가 없다. 아홉 언어의 글자 처리, 입력기, 화면 읽기 지원을 WebView는 이미 갖고 있다.
2. **화면은 같은 `frontendDist` 안의 다른 페이지다.** 안드로이드 창은 `ui/android.html`을 연다. 색 토큰, 글꼴, 문자열, `ipc.d.ts`, 기능 스크립트(고급 옵션의 `ADV_RULES`, 룸 옵션 표, 측정 파일 대응, EQ, 작업 폴링)는 데스크톱과 같은 파일을 쓴다. 마크업과 배치, 탐색, 진행 표시는 안드로이드 것이 따로 있다. 화면은 처리, 출력 복원, 설정, 정보 넷이고 녹음과 Stable은 없다. 데스크톱 `index.html`을 반응형으로 넓혀 한 페이지로 합치는 방식은 쓰지 않는다. 사이드바와 넓은 표를 전제로 한 배치를 좁은 화면에 맞추면 두 화면이 모두 나빠진다.
3. **녹음은 없다.** 안드로이드 빌드는 `impulcifer-service`와 `impulcifer-audio-io`를 `default-features = false`로 쓴다(`NullBackend`). cpal, `impulcifer-sys-win`, coreaudio-rs는 안드로이드 의존성 트리에 들어오지 않아야 하고 CI가 `cargo tree`로 확인한다. `bootstrap`의 `capabilities.recording`은 백엔드가 녹음할 수 있는지를 그대로 알린다.
4. **파일은 실제 경로로 다루고, 앱은 '모든 파일 접근' 권한을 받는다.** 서비스는 데스크톱과 같이 측정 폴더를 경로로 읽고 결과를 그 폴더에 쓴다. 권한(`MANAGE_EXTERNAL_STORAGE`)은 앱이 여는 시스템 설정 화면에서 사용자가 켠다. 권한이 없으면 화면은 폴더를 고르는 자리에서 그 사실과 켜는 방법을 알린다. 그래서 지원하는 가장 낮은 판은 이 권한이 생긴 안드로이드 11(API 30)이다.
5. **폴더와 파일은 앱 안의 탐색기로 고른다.** 새 IPC `list_directory`가 폴더의 목록을 주고, 화면이 그것으로 폴더와 파일을 고른다. 시작점은 셸이 알려 주는 저장소 볼륨이다. 시스템 선택기는 쓰지 않는다. 폴더를 고르지 못하고, 돌려주는 `content://` 주소를 경로로 바꾸는 일은 저장소 제공자마다 달라 일부에서만 된다.
6. **플랫폼만 아는 것은 Kotlin 플러그인 하나가 답한다.** `gen/android`의 `ImpulciferPlugin`이 권한 상태와 설정 화면 열기, 저장소 볼륨, 안드로이드 판과 기기 이름, 시스템의 밝기 테마, 창 배경과 시스템 막대의 색, 폴더를 파일 관리자로 열기를 맡는다. Rust는 Tauri의 안전한 API(`run_mobile_plugin`)로만 부르고 화면은 이 명령을 직접 부르지 못한다. 서비스는 `HostAdapter`의 `platform_info`, `storage_access`, `request_storage_access`, `storage_roots`로 받는다. `MainActivity`는 Rust가 시작하기 전에 `TMPDIR`을 앱의 캐시 폴더로 두고, 웹 화면을 시스템 막대와 키보드 사이에 놓는다.
7. **번들 데이터는 라이브러리에 넣어 앱 전용 폴더에 푼다.** 안드로이드 패키지 안의 파일은 경로로 열 수 없다. 처리에 쓰는 기본 테스트 신호 하나를 라이브러리에 넣고, 시작할 때 없거나 다르면 앱의 데이터 폴더에 쓴다. 녹음 재생용 sweep과 Harman 목표 곡선은 넣지 않는다. 설정 파일은 앱의 설정 폴더에 둔다.
8. **FFmpeg가 필요한 입력은 앱에서 지원하지 않는다.** 안드로이드 앱은 내려받은 실행 파일을 실행하지 못하므로 TrueHD·MLP 테스트 신호를 풀 수 없다. 탐색은 PATH만 보고(Termux에서 도는 CLI는 PATH의 FFmpeg를 쓴다) 데스크톱 리눅스의 경로는 보지 않으며, 찾지 못하면 안드로이드에 맞는 안내를 낸다.
9. **업데이트는 내려받기 링크를 여는 데까지다.** 설치 종류는 `apk`다. 업데이트 확인은 데스크톱과 같은 채널 규칙을 쓰고 릴리스의 APK 자산을 고른다. 받기를 누르면 그 주소를 브라우저로 열고, 설치는 사용자가 내려받은 파일을 열어 한다. 앱이 패키지를 직접 설치하지 않는다(설치 권한을 더 요구하게 된다).
10. **배포는 GitHub Release의 APK 하나다.** `release-3x.yml`이 `Impulcifer-<버전>-aarch64.apk`(arm64-v8a)를 릴리스에 올리고 `SHA256SUMS.txt`에 넣는다. 버전은 워크스페이스 버전이고 `versionCode`는 Tauri의 규칙(주×1000000 + 부×1000 + 수)을 따른다. 32비트와 x86-64용 APK는 내지 않는다. x86-64 빌드는 CI의 에뮬레이터 검사에만 쓴다. Play 스토어에는 올리지 않는다.
11. **서명 키는 저장소에 암호화해 둔다.** macOS(ADR 0012 7항)와 같은 방식이다. `apps/impulcifer-app/android-signing/`의 PKCS#12 키 저장소를 업데이터 서명 비밀값에서 유도한 암호로 잠그고, 키는 CI 작업 안에서만 풀린다. `.github/scripts/android_signing_key.sh`가 만들기, 서명, 지문 확인을 맡는다. 릴리스 작업은 APK의 서명 인증서가 저장소의 인증서와 같지 않으면 실패한다.
12. **검증은 에뮬레이터에서 화면으로 한다.** PR마다 CI가 x86-64 에뮬레이터에 앱을 깔고, 데모 측정 폴더를 화면에서 골라 BRIR을 만들고, 출력 하나를 지운 뒤 화면에서 복원해, 파일이 생겼는지 본다. 화면 그림은 갤러리가 휴대폰 크기로 낸다.

## 결과

- 데스크톱 앱의 동작과 출하물은 그대로다. 셸 코드가 `main.rs`에서 `lib.rs`로 옮겨졌고, 데스크톱 전용 의존성(대화상자, 업데이터, dark-light, Velopack, 녹음 백엔드)은 안드로이드가 아닌 대상에만 걸린다. `capabilities`는 공용(`default.json`)과 데스크톱용(`desktop.json`)으로 나뉜다.
- 화면에 옵션을 더할 때는 기능 스크립트 한 곳과 두 페이지의 마크업을 고친다. 안드로이드 페이지에 같은 id의 요소를 두지 않으면 그 옵션은 안드로이드에 나오지 않으므로, 갤러리의 안드로이드 시나리오가 요청 필드를 데스크톱 Studio와 비교한다.
- 업데이터 서명 비밀값을 바꾸면 안드로이드 키 저장소를 더는 풀 수 없다. 새 키로 서명한 APK는 기존 설치본 위에 깔리지 않으므로 사용자는 지우고 다시 깔아야 한다. 비밀값을 바꿔야 한다면 바꾸기 전에 옛 암호로 키를 풀어 새 암호로 다시 잠그는 절차를 먼저 만든다.
- '모든 파일 접근'은 Play 스토어가 파일 관리자 같은 앱에만 허용하는 권한이다. Play 배포를 하게 되면 저장소 접근을 복사 방식(시스템 선택기로 받은 폴더를 앱 전용 폴더로 가져오고 결과를 내보내기)으로 바꿔야 한다. 그 변경은 `HostAdapter`와 `list_directory` 뒤에서 끝난다.
- 다시 제안하지 말 것: 화면을 Slint로 다시 만드는 것, 시스템 선택기의 `content://` 주소를 경로로 바꿔 쓰는 것, 데스크톱 페이지 하나를 반응형으로 넓혀 안드로이드에 쓰는 것, 앱이 APK를 직접 내려받아 설치하는 것, Stable 스킨을 안드로이드에 옮기는 것.
- 확인하지 못한 채 둔 것: 시스템 테마가 앱이 열린 동안 바뀔 때 WebView의 `prefers-color-scheme`이 따라 바뀌는지, 폴더 열기가 제조사 파일 관리자마다 되는지. 둘 다 실패해도 처리와 복원에는 영향이 없다.
