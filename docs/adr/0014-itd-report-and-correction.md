# ADR 0014: 양 귀 도착 시차와 좌우 균형을 점검하고 보정하는 선택

- **상태:** 결정됨 (2026-11-06)
- **결정자:** 유지보수자 (115dkk)
- **관련:** ADR 0005·0008(정렬된 BRIR 위에 거는 가상 룸 튜닝), ADR 0011(헤드폰 측정 파일), ADR 0013(출력 파일만 바꾸는 선택의 선례)

## 맥락

2026-11-06의 2차 측정(DKK, 7.1.4 Dirac 측정 모드 녹음 두 벌과 헤드폰 보정 녹음 네 개)을 처리 전에 역컨볼루션해 보니 네 가지가 드러났다.

1. **입력 체인의 좌우 감도 차가 헤드폰 보정에서 두 배가 된다.** 인터페이스 입력 1이 입력 2보다 6.5 dB 낮았다. 스피커 녹음 때는 입력 1이 왼쪽 귀에, 헤드폰 녹음 때는 오른쪽 귀에 꽂혀 있었다. 헤드폰 보정(`stages/headphone.rs`)은 왼쪽 귀 응답을 0 dB로 맞춘 뒤 같은 양만큼 오른쪽도 옮기므로, 헤드폰 녹음의 좌우 차가 그대로 보정 이득이 된다. 스피커 쪽에서 왼쪽이 6.5 dB 낮고 보정이 오른쪽을 7 dB 올리니 최종 BRIR은 왼쪽 귀가 약 13.5 dB 작다. 처리 과정 어디에도 이것을 알리는 자리가 없다.
2. **머리 자세가 녹음마다 다르다.** 같은 사람의 1차는 정면(거울 쌍 ITD 합이 1샘플 안)이었고, 2차는 머리가 왼쪽으로 4~5° 돌아가 있었다(앞 쌍은 오른쪽 스피커의 |ITD|가, 뒤 쌍은 왼쪽 스피커의 |ITD|가 크다). 앞 쌍과 뒤 쌍의 합을 평균하면 회전이 서로 지워져 보이지 않는다.
3. **마이크 위치의 공통 오프셋과 고역 비대칭.** 센터와 서브의 ITD가 두 녹음 모두 −0.02 ms(오른쪽 귀가 1샘플 먼저)였고, 4~12 kHz의 좌우 차는 마이크를 다시 꽂을 때마다 부호가 바뀌었다.
4. **현재 정렬 단계는 ITD를 정수 샘플로만 다룬다.** `align_ipsilateral_all`은 센터의 두 귀를 상호상관의 정수 지연으로 맞추고, 거울 쌍은 같은 쪽 귀의 응답만 맞춘다. 스피커 안의 ITD는 녹음된 대로 남는다. 녹음 직후의 점검(`recording/checks.rs`)은 좌우가 바뀐 녹음, 돌아선 각도, 단계 사이의 ITD 차이는 잡지만 입력 감도 차와 머리 회전은 잡지 않는다.

유지보수자는 이것을 앱 기능으로 만들기로 했다. 측정한 사람이 처리 결과를 듣기 전에 숫자로 알 수 있어야 하고, 원하면 고칠 수 있어야 한다.

## 결정

1. **분석은 늘 하고 보정은 고른다.** BRIR 작업은 언제나 양 귀 도착 시차 보고서를 만든다. 보고서는 출력을 바꾸지 않는다. 보정은 3.x 확장 설정 `itd_mode`(`off`, `symmetric`, `model`)와 `head_radius`(cm, 5~15, 비우면 추정)로 고르고, 기본값 `off`에서는 모든 출력이 바이트 단위로 지금과 같다.
2. **ITD 추정은 구현 하나다.** 녹음 점검이 쓰는 추정(1.5 kHz 저역 통과, 직접음 앞 2 ms·뒤 3 ms 구간의 상호상관, 포물선 보간)을 `impulcifer-dsp`의 `itd` 모듈로 옮기고 녹음 점검과 처리 단계가 함께 부른다. 녹음 점검의 수치는 바뀌지 않는다(최대 지연 1 ms 그대로). 처리 단계는 최대 지연 1.5 ms로 부른다. 옆 스피커의 ITD가 1 ms에 가깝기 때문이다.
3. **재는 자리와 고치는 자리는 머리 자르기 직후다.** `crop_heads` 뒤, `align_ipsilateral_all` 앞이다. 그 뒤의 정렬은 스피커의 두 귀를 함께 옮기므로 스피커 안의 ITD를 바꾸지 않고, 센터의 정수 정렬은 보정이 센터를 정확히 0으로 둔 뒤에는 움직이지 않는다. 그룹 정렬이 끝난 뒤 한 번 더 재어 보정 뒤의 값으로 보고한다.
4. **보고서 내용.** 스피커마다 측정 ITD, 모델 ITD, 목표와 보정 뒤 ITD, 30~120 Hz 좌우 차. 거울 쌍마다 ITD 합과 머리 회전 추정. 요약으로 머리 회전(중앙값), 공통 오프셋(센터 자리의 평균), 입력 좌우 차(30~120 Hz 좌우 차의 중앙값), 머리 반지름(가장 옆에 있는 쌍에서 추정하거나 사용자 값), 4~12 kHz 비대칭. 헤드폰 보정을 켰으면 헤드폰 녹음의 좌우 차(200 Hz~2 kHz)와, 둘을 합친 **최종 BRIR의 예상 좌우 차**를 더하고 2 dB 이상이면 경고한다. 이 검사가 위 맥락 1의 13.5 dB를 잡는다.
5. **`symmetric`은 모델 없이 대칭만 만든다.** 먼저 공통 오프셋을 뺀다(센터 자리는 0으로, 나머지는 센터 자리 평균만큼). 그다음 거울 쌍마다 두 |ITD|의 평균을 목표로 두어 왼쪽은 +, 오른쪽은 −로 맞춘다. 짝이 없는 옆 스피커는 오프셋만 뺀다.
6. **`model`은 구형 머리 모델에 맞춘다.** 슬롯의 공칭 방향에서 Woodworth 식 `(r/c)(θ + sin θ)`로 목표를 만든다. 반지름 `r`은 `head_radius`이고, 비우면 가장 옆에 있는 쌍의 |ITD| 평균에서 거꾸로 구한다. 사람의 앞쪽 ITD는 이 모델보다 작게 나오는 일이 흔하므로 이 모드는 분명히 선택이고 기본이 아니다.
7. **보정은 한 귀를 늦추는 소수 샘플 지연이다.** 목표와 측정의 차이가 양이면 오른쪽 귀를, 음이면 왼쪽 귀를 그만큼 늦춘다. 앞당기지 않으므로 응답이 파일 앞으로 넘어가지 않는다. 지연은 FFT 위상(선형 위상)으로 걸고 길이는 그대로 둔다. 차이가 1.5 ms를 넘으면 그 스피커는 고치지 않고 알린다.
8. **녹음 점검도 넓힌다.** 측정마다 30~120 Hz 좌우 차를 재고, 한 녹음의 중앙값이 3 dB 이상이면 입력 감도 차를 경고한다. 헤드폰 보정 녹음은 같은 폴더의 앞선 스피커 녹음(참조 측정)과 견주어 예상 BRIR 좌우 차가 2 dB 이상이면 경고한다. 두 세션에서 마이크를 다른 입력에 꽂은 경우가 여기서 걸린다.
9. **전달 방법.** 작업 결과에 `alignment`를 넣고, 작업 기록에 요약을 남기며, 결과 폴더의 README에 표를 쓴다. 화면은 합성 탭에 `itd_mode`·`head_radius`를 두고 작업이 끝나면 표를 보여 준다.
10. **하지 않는 것.** 레벨 불균형을 자동으로 고치지 않는다. 녹음만으로는 장비 차이인지 사람의 차이인지 정할 수 없으므로 경고와 `channel_balance` 안내로 둔다. 4~12 kHz 비대칭도 보고만 한다. 반사음의 ITD를 따로 다루지 않는다(한 귀의 응답 전체를 같은 양만큼 늦춘다). 2.x는 바꾸지 않는다.

세부 수치와 알고리즘의 정본은 `docs/rust/ALIGNMENT.md`다.

## 결과

- `itd_mode = off`의 출력은 바이트 단위로 지금과 같다. `brir-3x.yml`에 `symmetric`과 `model` 시나리오(3.12.0부터)를 더한다.
- 작업 결과의 모양이 바뀐다(`alignment` 키). IPC 모양을 보는 테스트, `ipc.d.ts`, 갤러리 목 데이터, CLI `--info`를 함께 고친다.
- 참조 측정(`reference_measurements`)에 `lf_ild_db`가 생기고, 헤드폰 녹음도 참조 측정을 받는다.
- 다시 제안하지 말 것: ITD 보정을 `align_ipsilateral_all`의 정수 이동으로 대신하는 것, 두 귀를 반씩 당기고 미는 것(앞당김이 머리 구간을 넘을 수 있다), 레벨 불균형의 자동 보정, 앞 쌍과 뒤 쌍의 ITD 합을 평균해 머리 회전을 재는 것(회전이 지워진다).
