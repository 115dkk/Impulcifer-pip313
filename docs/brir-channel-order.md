# hrir.wav와 hesuvi.wav의 채널 순서

Impulcifer가 만드는 `hrir.wav`와 `hesuvi.wav`는 같은 임펄스 응답을 담고 있고, 트랙을 늘어놓는 순서만 다릅니다. 두 파일을 오디오 편집기로 열거나 다른 컨볼버로 옮길 때 몇 번째 트랙이 어느 스피커의 소리를 어느 귀로 보내는지 헷갈리기 쉬워서, 트랙 하나하나를 이 문서에 적어 둡니다.

기준 코드는 2.x의 `core/constants.py`(`HEXADECAGONAL_TRACK_ORDER`, `HESUVI_TRACK_ORDER`)와 3.x의 `crates/impulcifer-types/src/constants.rs`입니다. 아래 hrir.wav·hesuvi.wav 표의 32·30트랙은 두 버전이 같고, 3.x 쪽은 2.x에서 뽑은 골든 파일과 대조하는 테스트가 있습니다. 3.x는 몰입형 포맷을 위해 스피커 25개를 더해 그 뒤에 트랙을 이어 붙이고, 포맷마다 공식 채널 순서로 된 파일을 하나씩 더 씁니다([3.x: 몰입형 포맷](#3x-몰입형-포맷) 참고). 이 문서의 표는 `tests/test_channel_order_doc.py`(2.x 표)와 `crates/impulcifer-types/tests/channel_order_doc.rs`(3.x 표)가 코드와 한 줄씩 대조하므로, 코드의 순서가 바뀌면 표도 함께 고쳐야 테스트가 통과합니다.

## 스피커 하나에 트랙이 둘인 이유

FL 스피커에서 나온 소리는 왼쪽 귀와 오른쪽 귀에 모두 들어갑니다. 두 귀에 닿는 소리는 도착 시각도, 크기도, 음색도 다르므로 Impulcifer는 둘을 따로 측정해 따로 저장합니다. 그래서 가상 스피커 하나마다 WAV 트랙이 두 개 있고, 스피커 7개를 담은 `hesuvi.wav`는 14트랙이 됩니다.

재생할 때도 두 트랙은 따로 쓰입니다. 컨볼버는 재생하는 오디오의 FL 채널 하나를 `FL-left` 트랙과 합성곱해 헤드폰 왼쪽으로, `FL-right` 트랙과 합성곱해 헤드폰 오른쪽으로 보냅니다. 헤드폰 왼쪽 출력은 모든 스피커의 `-left` 트랙 결과를 더한 것이고, 오른쪽 출력은 모든 `-right` 트랙 결과를 더한 것입니다.

```text
헤드폰 왼쪽  = Σ (재생 오디오의 스피커 s 채널) ⊛ (s-left 트랙)
헤드폰 오른쪽 = Σ (재생 오디오의 스피커 s 채널) ⊛ (s-right 트랙)
```

이 문서는 두 낱말을 구분해 씁니다.

- **스피커:** FL, FR, SL처럼 가상 스피커 위치 하나를 가리키며, 재생하는 오디오의 채널 하나와 같습니다. 'FL 채널'이라는 말은 대개 이 뜻입니다.
- **트랙:** WAV 파일의 채널 하나를 가리킵니다. 스피커 하나와 귀 하나의 조합이므로 스피커 하나는 트랙 두 개입니다. README에서 'hesuvi.wav의 앞 14채널'이라고 할 때의 채널은 이 트랙입니다.

## 트랙 이름 읽는 법

트랙 이름은 `<스피커>-<귀>` 형식입니다. 뒤에 붙은 `left`와 `right`는 스피커가 놓인 쪽이 아니라 **그 소리를 듣는 귀**입니다.

| 트랙 이름 | 뜻 | 스피커와 귀 |
| --- | --- | --- |
| `FL-left` | 왼쪽 앞 스피커의 소리를 왼쪽 귀가 들은 응답 | 같은 쪽 |
| `FL-right` | 왼쪽 앞 스피커의 소리를 오른쪽 귀가 들은 응답 | 반대쪽 |
| `FR-left` | 오른쪽 앞 스피커의 소리를 왼쪽 귀가 들은 응답 | 반대쪽 |
| `FR-right` | 오른쪽 앞 스피커의 소리를 오른쪽 귀가 들은 응답 | 같은 쪽 |
| `FC-left` | 가운데 스피커의 소리를 왼쪽 귀가 들은 응답 | 가운데 |
| `FC-right` | 가운데 스피커의 소리를 오른쪽 귀가 들은 응답 | 가운데 |

'같은 쪽'은 스피커와 귀가 머리의 같은 편에 있는 경우(ipsilateral)이고, '반대쪽'은 소리가 머리를 돌아 반대편 귀에 닿는 경우(contralateral)입니다. 반대쪽 트랙은 같은 쪽 트랙보다 늦고 작게 들어옵니다. FC와 LFE는 가운데에 있어 어느 쪽에도 속하지 않습니다.

귀의 좌우는 녹음 파일에서 정해집니다. Impulcifer는 스피커 녹음 WAV(`FL,FR.wav` 등)의 첫째 채널을 왼쪽 귀 마이크로, 둘째 채널을 오른쪽 귀 마이크로 읽습니다(`core/hrir.py`의 `_ingest_recording`). 녹음할 때 마이크를 좌우 바꿔 끼웠다면 모든 `-left`와 `-right`가 뒤바뀝니다.

## WAV 번호와 인덱스

아래 표는 번호를 두 가지로 적습니다.

- **WAV 번호:** 1부터 셉니다. Audacity, REAPER 같은 편집기와 HeSuVi·Equalizer APO 관련 글이 쓰는 번호입니다.
- **인덱스:** 0부터 셉니다. Python에서 `soundfile.read(..., always_2d=True)`로 읽은 배열의 `data[:, 인덱스]`입니다.

두 파일 모두 **홀수 WAV 번호는 왼쪽 귀, 짝수 WAV 번호는 오른쪽 귀**이며, 확장 트랙까지 예외가 없습니다. 두 파일은 각 번호에 어느 스피커가 오느냐만 다릅니다.

## hrir.wav

스피커를 FL, FR, FC, LFE, BL, BR, SL, SR 순서로 놓고, 스피커마다 왼쪽 귀, 오른쪽 귀 순서로 트랙을 둡니다. 앞 8개 스피커의 순서는 Windows 7.1 WAV(WAVEFORMATEXTENSIBLE)의 채널 순서와 같습니다. 코드에서는 이 배치를 `HEXADECAGONAL_TRACK_ORDER`(16각형, 곧 기본 16트랙)라고 부릅니다.

이 파일에서는 **이웃한 두 트랙(1·2, 3·4, 5·6, ...)이 언제나 같은 스피커**입니다.

LFE 자리(7·8번)는 항상 무음입니다. Impulcifer는 LFE를 측정하지 않지만, 뒤 트랙들의 위치를 표준 순서에 맞추려고 자리를 비워 둡니다. 17번부터는 이 포크가 더한 와이드·상단 스피커(WL, WR, TFL, TFR, TSL, TSR, TBL, TBR)이고, 측정하지 않은 뒤쪽 스피커는 파일에서 빠집니다(아래 '트랙 수가 14나 16이 아닐 때' 참고).

## hesuvi.wav

HeSuVi가 정한 14트랙 배치를 따릅니다. 앞 7트랙은 왼쪽 스피커 FL, SL, BL을 같은 쪽 귀(왼쪽), 반대쪽 귀(오른쪽) 순서로 적고 FC의 왼쪽 귀로 끝납니다. 뒤 7트랙은 앞 7트랙의 좌우를 뒤집은 거울상으로, 오른쪽 스피커 FR, SR, BR을 같은 쪽 귀(오른쪽), 반대쪽 귀(왼쪽) 순서로 적고 FC의 오른쪽 귀로 끝납니다. n번 트랙 이름의 좌우를 모두 바꾸면 n+7번 트랙이 됩니다(`FL-left`와 `FR-right`, `FL-right`와 `FR-left`, ..., `FC-left`와 `FC-right`).

그 결과 이 파일에서는 **이웃한 두 트랙이 같은 스피커라는 규칙이 7번부터 맞지 않습니다.** FC가 7번과 14번으로 떨어져 있어 FR은 8·9번, SR은 10·11번, BR은 12·13번을 차지하고, 이 세 스피커는 오른쪽 귀 트랙이 먼저 옵니다. 홀수 번호가 왼쪽 귀라는 규칙은 그대로이므로 8번(짝수)이 `FR-right`, 9번(홀수)이 `FR-left`입니다.

마지막 열은 HeSuVi가 Equalizer APO 설정에서 각 트랙에 붙이는 가상 채널 이름입니다. HeSuVi 설정의 `Channel: L0 R1 SL0 SR1 RL0 RR1 C0 R0 L1 SR0 SL1 RR0 RL1 C1` 줄이 WAV 1~14번에 차례로 대응합니다. 15번부터는 이 포크가 붙인 확장 트랙이고 HeSuVi는 쓰지 않습니다([무음 채널과 HeSuVi 호환성](silent-channel-compatibility.md) 참고). 확장 트랙의 순서는 hrir.wav의 확장 부분과 같아서 스피커마다 왼쪽 귀, 오른쪽 귀 순서입니다.

## 헷갈리기 쉬운 곳

실제로 자주 틀리는 대목을 모았습니다.

- **hesuvi.wav의 FR은 8번이 오른쪽 귀, 9번이 왼쪽 귀입니다.** SR(10번 오른쪽, 11번 왼쪽)과 BR(12번 오른쪽, 13번 왼쪽)도 같은 식입니다. 두 트랙씩 끊어 앞을 왼쪽 귀로 읽으면 7번부터 모두 틀립니다.
- **FC는 hesuvi.wav에서 7번과 14번으로 떨어져 있습니다.** hrir.wav에서는 5·6번에 붙어 있습니다.
- **사이드와 백의 순서가 파일마다 다릅니다.** hrir.wav는 BL·BR(9~12번)이 SL·SR(13~16번)보다 앞이고, hesuvi.wav는 왼쪽 절반에서 SL(3·4번)이 BL(5·6번)보다 앞입니다. 다른 도구가 만든 16트랙 BRIR 중에는 사이드를 백보다 먼저 두는 배치(L, R, C, LFE, LS, RS, LB, RB)를 쓰는 것도 있어서([예](https://www.head-fi.org/threads/recording-impulse-responses-for-speaker-virtualization.890719/page-71)), hrir.wav를 그런 설정에 그대로 넣으면 사이드와 백이 서로 바뀝니다.
- **HeSuVi 가상 채널 이름의 글자는 스피커가 아니라 소리가 가는 귀를 가리킵니다.** `L0`, `L1`, `SL0`, `SL1`, `RL0`, `RL1`, `C0`은 왼쪽 귀로, `R0`, `R1`, `SR0`, `SR1`, `RR0`, `RR1`, `C1`은 오른쪽 귀로 갑니다. 숫자 0은 귀와 같은 쪽 스피커, 1은 반대쪽 스피커입니다(C는 0이 왼쪽 귀, 1이 오른쪽 귀). 그래서 `R1`은 FR 스피커가 아니라 FL 입력을 오른쪽 귀로 보내는 채널이고, `L1`은 FR 입력을 왼쪽 귀로 보내는 채널입니다. HeSuVi 설정은 `Copy: L0=LVI R1=LVI ... R0=RVI L1=RVI ...`로 FL 입력(LVI)을 `L0`와 `R1`에, FR 입력(RVI)을 `R0`와 `L1`에 복사합니다([HeSuVi 토론 게시판](https://sourceforge.net/p/hesuvi/discussion/general/thread/4d3e1909a1/)).
- **HeSuVi는 백 스피커를 RL·RR(rear)이라고 부릅니다.** Impulcifer의 BL·BR과 같은 스피커이고, SL·SR은 양쪽 모두 사이드 스피커입니다.
- **hesuvi.wav의 순서를 손으로 고치지 마세요.** HeSuVi 게시판에 Impulcifer가 만든 hesuvi.wav의 2번과 9번, 4번과 11번, 6번과 13번을 맞바꿔야 한다는 글이 올라온 적이 있지만, 위의 `Channel:` 줄과 대조하면 현재 순서가 맞습니다. 맞바꾸면 FL 입력을 오른쪽 귀로 보낼 때 FR 스피커의 왼쪽 귀 응답을 쓰게 되어, 좌우 스피커의 반대쪽 귀 응답이 서로 뒤바뀝니다. 방과 머리가 좌우 대칭에 가까우면 두 응답이 비슷해 들어서는 잘 드러나지 않으므로, 이 실수는 알아차리기 어렵습니다.
- **LFE 자리는 hrir.wav에만 있습니다.** hrir.wav의 7·8번은 항상 무음이고, hesuvi.wav에는 LFE 트랙이 없습니다.
- **번호를 1부터 세는지 0부터 세는지 확인하세요.** 편집기의 '채널 9'는 Python의 `data[:, 8]`입니다.

## 트랙 수가 14나 16이 아닐 때

기본 설정에서는 hesuvi.wav의 앞 14트랙과 hrir.wav의 앞 16트랙을 항상 남기고, 그 뒤의 확장 스피커는 마지막으로 응답이 있는 스피커까지만 남깁니다. 그래서 hesuvi.wav는 14~30트랙, hrir.wav는 16~32트랙이 되고, 트랙 수는 언제나 짝수입니다. 이때도 번호는 위 표와 같고 끝만 잘립니다. 측정하지 않은 스피커(예를 들어 FL·FR만 측정했을 때의 SL, BL, FC)도 앞 14·16트랙 안에서는 무음 트랙으로 자리를 지킵니다. 그렇게 하는 이유는 [무음 채널과 HeSuVi 호환성](silent-channel-compatibility.md)에 있습니다.

`--remove_silent_channels`(GUI의 '중간 무음 채널도 제거')를 켜면 중간의 무음 트랙까지 빠지므로 **위 표의 번호가 맞지 않습니다.** 남은 트랙의 상대 순서는 유지되고, 각 트랙의 이름은 WAV 안의 `ICHL` 청크에 `{"version":1,"tracks":["FL-left", ...]}` 형식으로 저장됩니다. 이 청크는 `core/brir_layout.py`의 `read_track_names`로 읽을 수 있습니다. 이렇게 만든 파일을 HeSuVi처럼 고정 배치를 기대하는 프로그램에 그대로 쓰면 스피커가 엉뚱한 자리에 배정됩니다.

## 다른 출력 파일

옵션으로 만드는 다른 파일도 트랙 이름 규칙이 같고, 모두 홀수 번호가 왼쪽 귀입니다.

| 파일 | 트랙 순서 |
| --- | --- |
| `jamesdsp.wav` (`--jamesdsp`) | `FL-left`, `FL-right`, `FR-left`, `FR-right`의 4트랙 |
| `Hangloose/<스피커>.wav` (`--hangloose`) | `<스피커>-left`, `<스피커>-right`의 2트랙. 스피커마다 파일이 하나씩 생깁니다. |
| `truehd_11ch_<N>ch.wav`, `truehd_13ch_<N>ch.wav` (`--output_truehd_layouts`) | TrueHD 순서에서 측정한 스피커만 골라 스피커마다 왼쪽 귀, 오른쪽 귀 순서로 적습니다. 11ch는 FL, FR, FC, BL, BR, SL, SR, TFL, TFR, TBL, TBR이고, 13ch는 TFR과 TBL 사이에 TSL, TSR이 더 들어갑니다. |

TrueHD 파일은 측정하지 않은 스피커의 자리를 비워 두지 않고 건너뜁니다. 파일 이름의 N이 실제로 담긴 스피커 수이고, 빠진 스피커가 있으면 그 뒤 스피커들의 번호가 앞당겨집니다.

## 3.x: 몰입형 포맷

3.x는 NHK 22.2, Auro-3D 13.1, Dolby Atmos 24.1.10, DTS:X Pro 30.2를 다룹니다. 결정과 근거는 [ADR 0007](adr/0007-immersive-layouts.md)에 있습니다. 이 절은 파일에 무엇이 어디에 들어가는지만 적습니다.

### 스피커 코드는 위치를 가리킵니다

포맷마다 같은 라벨이 다른 위치를 가리킵니다. 22.2의 `FL`은 왼쪽 60°이고 왼쪽 30°는 `FLc`입니다. DTS의 `Lb`는 귀 아래 앞쪽이고 Auro의 `Lb`는 귀 높이 뒤쪽입니다. 그래서 Impulcifer는 녹음 파일 이름과 트랙 이름에 포맷 라벨을 쓰지 않고, 위치로 정한 스피커 코드를 씁니다. 22.2 리그의 왼쪽 60° 스피커는 `WL.wav`로, 왼쪽 30° 스피커는 `FL.wav`로 녹음해야 합니다. 포맷 라벨대로 60° 스피커를 `FL.wav`로 부르면 그 응답이 22.2 파일의 7·8번 트랙(FLc)에 들어가고, 소리만으로는 알아채기 어렵습니다.

2.x의 15개 코드(FL FR FC BL BR SL SR WL WR TFL TFR TSL TSR TBL TBR)에 아래 25개가 더해졌습니다. 방위각은 앞에서 왼쪽·오른쪽으로 잰 각도이고, 고도는 귀 높이에서 위가 +입니다. hrir.wav와 hesuvi.wav는 2.x 트랙 뒤에 이 순서로 스피커마다 왼쪽 귀, 오른쪽 귀 트랙을 붙이며, 끝의 측정하지 않은 스피커는 지금처럼 잘라 냅니다. 그래서 2.x 스피커만 측정했다면 두 파일은 예전과 같습니다.

### 포맷 파일

측정한 스피커가 한 포맷의 채널을 모두 덮으면 hrir.wav, hesuvi.wav와 함께 그 포맷의 파일이 생깁니다. 채널마다 왼쪽 귀, 오른쪽 귀 두 트랙을 포맷의 공식 순서대로 적으므로, 홀수 WAV 번호가 왼쪽 귀라는 규칙은 여기서도 같습니다. LFE 채널은 측정하지 않으므로 제자리에 무음 두 트랙으로 남깁니다. 이 파일은 중간 무음 제거 옵션을 켜도 트랙을 빼지 않고, `ICHL` 청크에 포맷 라벨로 된 트랙 이름(`TpFL-left` 등)을 담습니다.

`--layout_files`(설정 `layout_files`)로 바꿀 수 있습니다. 기본값 `auto`는 빠짐없이 측정한 포맷만 쓰고, `none`은 포맷 파일을 쓰지 않습니다. `22.2`, `13.1`, `24.1.10`, `30.2`를 쉼표로 나열하면 그 포맷은 일부만 측정해도 쓰고, 빠진 채널은 무음으로 둔 채 로그와 README.md에 알립니다. 9.1.6처럼 Atmos의 일부만 측정한 경우 Atmos 순서 파일이 필요하면 `--layout_files=24.1.10`을 쓰면 됩니다. 측정이 어떤 포맷의 절반 이상을 덮는데 몇 채널이 빠졌다면, 무엇이 빠졌는지 포맷 라벨과 코드로 알려 줍니다.

## 직접 확인하기

트랙의 귀 배정이 맞는지는 소리가 도착한 시각과 크기로 확인할 수 있습니다. 같은 스피커의 두 트랙 가운데 같은 쪽 귀 트랙이 반대쪽 귀 트랙보다 먼저, 크게 들어와야 합니다. 아래 코드는 각 트랙이 피크의 10분의 1(-20 dB)을 처음 넘는 시각과 피크 레벨을 출력합니다.

```python
import numpy as np
import soundfile as sf

data, fs = sf.read("hesuvi.wav", always_2d=True)
for i in range(data.shape[1]):
    x = np.abs(data[:, i])
    peak = x.max()
    if peak == 0:
        print(f"WAV {i + 1:2d}: 무음")
        continue
    onset_ms = np.argmax(x >= peak * 0.1) / fs * 1000
    print(f"WAV {i + 1:2d}: 도착 {onset_ms:6.3f} ms, 피크 {20 * np.log10(peak):6.1f} dBFS")
```

저장소의 데모 데이터(`data/demo`)를 기본 옵션으로 처리한 hesuvi.wav에서는 아래처럼 나옵니다(2.x, Linux 기준이며 실행 환경에 따라 레벨의 소수점 아래 값은 조금 다를 수 있습니다).

| WAV 번호 | 트랙 | 도착 | 피크 |
| ---: | --- | ---: | ---: |
| 1 | `FL-left` | 0.979 ms | -32.6 dBFS |
| 2 | `FL-right` | 1.188 ms | -42.9 dBFS |
| 7 | `FC-left` | 0.979 ms | -35.2 dBFS |
| 8 | `FR-right` | 0.979 ms | -32.4 dBFS |
| 9 | `FR-left` | 1.167 ms | -39.3 dBFS |
| 14 | `FC-right` | 0.979 ms | -35.5 dBFS |

FL은 왼쪽 귀(1번)가 0.21 ms 먼저, 10 dB 크게 들어오고, FR은 오른쪽 귀(8번)가 먼저, 크게 들어옵니다. FC는 두 귀에 같은 시각, 거의 같은 크기로 들어옵니다. 자기 측정에서 이 관계가 모든 스피커에서 좌우 반대로 나온다면, 녹음할 때 마이크나 오디오 인터페이스 입력의 좌우가 바뀌었을 가능성이 큽니다.
