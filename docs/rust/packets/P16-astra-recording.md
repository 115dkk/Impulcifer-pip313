## Design rules
- The IPC surface and the frontend are 2.x as they are. `start_recording`, `list_audio_devices`, `resolve_recording_paths` keep their request and response shapes and error codes exactly (survey sections 1 and 4). Recording jobs are `kind = "recording"`, `cancellable = false`, and emit only `status` and `progress` events with the flat ten-key `RecorderProgressEvent` payload.
- Windows has WASAPI only (ADR 0002). The 2.x `host_api` field stays accepted: `list_audio_devices` reports the backend's single host API name (`impulcifer-sys-win` reports `"Windows WASAPI"`; cpal reports its host name), an unknown `host_api` is still `INVALID_REQUEST "Unknown host API."`, and device resolution by name follows the 2.x rules minus the preference walk (there is one host API): exact name match wins, else a unique word-substring match, else `DEVICE_ERROR` with the `DeviceNotFoundError` message shape (`'No device found with name "<name>" and host API "<api>". '`, the channel-shortfall message). `Endpoint` ids from `enumerate()` are the stable identity; the request carries names because the frontend sends names.
- Format policy is the audio-io one (exclusive first, shared + auto-convert on `UnsupportedFormat`), not the sounddevice probe; document that the 2.x "auto-convert only when the native probe fails" rule is implemented by `open_*_with_policy`.
- Progress is wall-clock like 2.x (a timer thread emitting `event_for_elapsed` every 250 ms from the moment playback starts), but since `play_and_record` also reports `SessionEvent::Progress { frames_played, frames_total }`, prefer the stream position when available and fall back to wall clock; the `0.98 / 0.99 / 1.0` ladder and the phase names are unchanged.
- 2.x cannot cancel a recording. 3.x may: pass the job's `CancelToken` into `play_and_record` and report `cancellable: true` only if you also update `bootstrap.capabilities.recording_cancel` to `true` and verify `webview_ui/app.js` handles a cancelled recording job (it renders `webview_status_cancelled` and `finishRecorderStatus` on any terminal status). If either is not clean, keep `cancellable = false` and say so.
