# 3.x 앱 화면

## 파일과 문자열

3.x 화면은 `apps/impulcifer-app/ui/`에 있습니다. `index.html`, `app.js`, `styles.css`와 로고·글꼴은 Tauri의 `frontendDist` 안에서 제공하며, 프레임워크나 번들러는 사용하지 않습니다. 글꼴은 기존 Pretendard와 JetBrains Mono를 그대로 쓰고 라이선스도 함께 포함합니다.

`webview_ui/`와 `i18n/locales/`는 2.x 파일입니다. 3.x 변경에서는 수정하지 않습니다. 새 문자열과 기존 문구의 수정은 `crates/impulcifer-service/locales/<언어>.json` 아홉 파일에 넣습니다. 서비스와 화면 검사 도구는 2.x 영어, 2.x 해당 언어, 오버레이 영어, 오버레이 해당 언어 순서로 합칩니다. 같은 키가 있으면 뒤의 값이 이깁니다.

모든 오버레이는 키 집합과 `{placeholder}` 집합이 같아야 합니다. 키를 바꾸지 않고 문구만 번역하며, 페이지에서는 `t()`와 `fmt()`로 표시합니다. 실행 정보의 선택적인 값이 없으면 해당 행은 표시하지 않습니다. 설정의 폴더 표시는 `get_system_info().paths`를 사용하고, 설정 파일의 열기 버튼은 부모 폴더를 `open_path`에 전달합니다.

## 타입을 검사하는 IPC

`apps/impulcifer-app/ui/ipc.d.ts`가 24개 IPC 메서드의 위치 인자, 요청, 응답, 작업 스냅샷과 이벤트를 선언합니다. `Envelope<T>`는 `ok`로 구분하는 합집합입니다. `ok`를 확인한 뒤 성공의 `data` 또는 실패의 `error`를 사용합니다. 작업은 `kind`, 이벤트는 실제 전송 필드인 `type`으로 구분합니다. 초기 스크립트와 스모크 드라이버가 쓰는 `Window` 속성도 이 파일에서 선언합니다.

JS에서는 JSDoc으로 선언을 참조합니다. `$()`는 필수 HTML 요소를 찾고, `el(id, HTMLInputElement)` 같은 호출은 실제 DOM 생성자를 검사해 정확한 요소 타입을 반환합니다. `unknown`은 확인하지 않은 전송 값에만 사용합니다. `any`, 타입 검사 생략 주석, 느슨한 컴파일러 설정은 사용하지 않습니다.

IPC 메서드를 추가할 때는 다음 항목을 함께 수정합니다.

1. Rust의 `IpcMethod`, 서비스 구현, 정책 목록, `features.toml`에 메서드를 등록하고 검증 테스트를 연결합니다.
2. `ipc.d.ts`에 요청·응답 구조와 `IpcApi`의 위치 인자 시그니처를 적습니다. 브리지 프록시는 같은 이름을 전달하므로 메서드별 분기를 만들지 않습니다.
3. 페이지에서 실패 봉투를 처리하고, 필요한 문자열을 아홉 오버레이에 추가합니다.
4. 갤러리의 모의 IPC와 필요한 스모크 검사를 갱신한 뒤 타입·계약·카탈로그 검사를 실행합니다.

## Studio와 Stable

두 스킨은 Pulse Studio의 색상 토큰과 카드·필드·칩을 공유하며 밝은 테마와 어두운 테마를 지원합니다. Studio는 사이드바와 작업 진행 카드를 사용합니다. Stable은 상단 탭과 기존 작업 모달을 유지합니다. 스킨·테마·언어 선택의 ID는 `sf-skin`, `sf-theme`, `sf-language`입니다. 3.x에는 CustomTkinter 선택 항목이 없습니다.

녹음 화면의 `rf-share-mode`는 bootstrap의 `capabilities.share_modes`로 채웁니다. `auto`만 있으면 선택을 비활성화하고 Windows WASAPI에서만 고정 모드를 지원한다는 안내를 표시합니다. `rf-host-api`는 요청에서 유지하되 호스트 API가 하나 이하이면 행을 숨깁니다. 고정 모드를 거부한 오류는 상태와 로그에 표시하고 Stable에서는 알림도 띄웁니다. 성공하면 실제 출력·입력 모드를 표시합니다.

## Studio 복원 목록

`recovery-inventory`는 폴더와 두 옵션을 마지막으로 바꾼 뒤 300ms 후 `plan_output_recovery`를 호출합니다. 각 요청에 증가하는 번호를 부여하고 오래된 응답은 무시합니다. 같은 값의 `input`과 `change`는 중복 요청하지 않습니다. 다시 확인하는 동안 기존 목록의 높이는 유지하되 내용은 숨겨, 포커스 이동 중 아래 체크박스가 움직이지 않도록 합니다.

| `data-state` | 표시와 실행 버튼 |
|---|---|
| `empty` | 폴더 선택 안내, 실행 불가 |
| `planning` | 파일 확인 중 안내, 실행 불가 |
| `ready` | 원본·샘플레이트·길이·스피커·파일 목록, 실행 가능 |
| `nothing` | 요청한 파일이 모두 있다는 안내, 실행 불가 |
| `error` | 오류 코드와 메시지, 오류색 테두리, 실행 불가 |

`recovery-ledger`는 `existing_files`와 `planned_files`의 실제 파일만 표시합니다. 상대 파일명과 `present`, `planned`, `created` 상태를 각각 `data-file`, `data-status`에 기록합니다. 기존 파일은 그대로 유지하고, 실행으로 만든 파일의 상태만 `created`로 바꿉니다. 실행 도중 폴더나 옵션을 바꾸었다면 이전 실행 결과를 새 목록에 적용하지 않습니다.

세 카드와 기존 결과 ID는 유지합니다. 성공 시 요약과 출력 폴더 열기 버튼을 표시합니다. Stable은 목록을 숨기고 계획 IPC를 호출하지 않습니다. Stable의 복원 버튼은 계획 상태 때문에 비활성화하지 않으며 입력 검증은 서비스가 담당합니다. 두 스킨 모두 다른 작업이 실행 중이면 새 작업을 시작하지 못합니다.

## 안드로이드 화면

안드로이드 앱은 같은 Tauri 셸이 `ui/android.html`을 엽니다(ADR 0020). 한 손으로 쥐고 엄지로 누르는 휴대폰에 맞춰 마크업과 배치, 탐색, 작업 표시를 따로 만든 페이지입니다. 녹음과 Stable 스킨은 없습니다. 화면은 처리, 출력 복원, 설정, 정보 넷이고 아래쪽 탐색 막대로 오갑니다. 처리와 출력 복원 화면에는 그 화면의 주요 버튼 하나가 탐색 막대 위에 붙어 있습니다.

두 페이지는 기능 스크립트를 함께 씁니다. `android.html`은 `core.js`, `progress.js`, `jobs.js`, `update.js`, `test-signal.js`, `tips.js`, `room.js`, `advanced.js`, `eq.js`, `mfile.js`, `settings.js`를 데스크톱과 같은 파일로 읽고, 안드로이드에만 있는 `chrome.js`(앱 막대, 화면 전환, 뒤로 가기), `storage.js`(모든 파일 접근), `chooser.js`(폴더와 파일 고르기), `sheet.js`(작업 시트), `tipsheet.js`(설명 시트), `optionsheet.js`(선택 시트)를 더 읽은 뒤 `app.js`로 끝납니다. `recorder.js`와 `guide.js`는 읽지 않습니다. 필드의 ID도 Studio와 같습니다(`bf-…`, `ba-…`, `dis-…`, `recovery-…`, `sf-…`, `btn-…`). 그래서 `ADV_RULES`, `ROOM_FIELDS`, 측정 파일 대응, 요청 조립이 고치지 않은 채로 두 페이지에서 돌고, 같은 선택은 같은 BRIR 요청이 됩니다.

기능 하나는 그 마크업이 있는 페이지에서만 돕니다. `app.js`의 `FEATURES` 항목은 `root`에 요소 ID 하나를 적고, 그 요소가 페이지에 없으면 그 기능의 `wire`, `render`, `addArgs`, `boot`, `load`, `ready`, `job`을 하나도 부르지 않습니다. `boot()`는 이 훅을 표의 순서대로 도는 루프입니다. 두 페이지가 한 가지 일을 다르게 할 때는 플랫폼 이름이 아니라 마크업으로 나눕니다. 찾아보기 버튼은 페이지에 `#chooser`가 있으면 그 시트를 열고 없으면 시스템 대화상자를 엽니다. 설명 버튼은 `#tip-sheet`가 있으면 아래에서 올라오는 시트로, 없으면 버튼 옆 말풍선으로 설명을 보여 줍니다. 선택 상자(`<select>`)는 `#option-sheet`가 있으면 옵션을 그 시트로 보여 주고, 없으면 브라우저의 목록을 씁니다. 녹음과 안내 기능은 안드로이드가 읽지 않는 파일에 있으므로 표에서 화살표 함수로 감싸 둡니다.

다른 코드가 기대는 이름은 바꾸지 않습니다.

- 페이지 표시: `<html data-page="android">`, 데스크톱은 `data-page="desktop"`. `boot()`가 끝나면 두 페이지 모두 `data-booted="true"`를 답니다.
- 작업 상태: `renderJobState`가 뿌리 요소에 `data-job-kind`(`brir`, `output_recovery`, 없음)와 `data-job-status`(`running`, `cancel_requested`, `succeeded`, `failed`, `cancelled`, `idle`)를 적습니다.
- 탐색: `.nav-item`과 `data-view`, `nav-processing`, `nav-recovery`, `nav-settings`, `nav-info`. 화면은 `view-processing`, `view-recovery`, `view-settings`, `view-info`입니다.
- 고르기 시트: `#chooser`, `#chooser-name`(지금 폴더의 이름, 볼륨의 뿌리에서는 볼륨 이름), `#chooser-path`(그 폴더의 전체 경로, 길면 앞쪽이 잘립니다), `#chooser-roots`, `#chooser-list`, `#chooser-up`, `#chooser-select`, `#chooser-close`. 저장소 안내는 `#storage-notice`와 `#btn-storage-access`, 작업 시트는 `#job-sheet`와 `#job-sheet-close`입니다.
- 선택 시트: `#option-sheet`, `#option-sheet-title`, `#option-sheet-list`와 그 안의 `.option-row`(지금 고른 옵션은 `aria-selected="true"`), 바깥의 `#option-scrim`.
- `bf-dir-path`와 `recovery-dir-path`는 사람이나 시험이 경로를 직접 입력할 수 있는 입력란입니다.

폴더와 파일은 `list_directory`로 앱 안에서 고릅니다. 시트는 필드에 적힌 폴더가 있으면 그 폴더에서, 없으면 첫 저장소 볼륨에서 열립니다. 볼륨이 둘 이상이면 칩으로 보입니다. 목록 위에는 지금 폴더의 이름(볼륨의 최상위에서는 볼륨 이름)과 그 아래 전체 경로가 있고, 경로가 길면 앞쪽이 잘려 끝부분이 보입니다. 폴더 모드와 파일 모드가 같은 모양입니다. 폴더 모드에서는 폴더만 고를 수 있고 파일은 흐리게 보이며, 파일 모드에서는 그 필드가 받는 종류의 파일을 눌러 고릅니다. 불러오는 중, 빈 폴더, 목록이 잘린 폴더, 읽을 수 없는 폴더, 접근 권한 없음이 각각 따로 표시됩니다. 모든 파일 접근은 `get_storage_access`로 묻고, 권한이 없으면 처리 화면 맨 위와 고르기 시트에 같은 안내와 설정 열기 버튼(`request_storage_access`)을 보여 줍니다. 사람이 앱 밖에서 권한을 켜므로 페이지가 다시 보일 때(`visibilitychange`)마다 상태를 다시 묻습니다. 설정 화면은 권한 상태를 한 줄로 알리고, 권한이 없을 때만 설명과 설정 열기 버튼을 보입니다. 권한이 있으면 거기서 할 일이 없기 때문입니다.

선택 상자는 옵션을 앱의 시트로 보여 줍니다(3.22.1). 안드로이드 WebView는 `<select>`를 누르면 시스템의 목록 대화상자를 띄우는데, 색과 모양이 앱과 맞지 않습니다. `optionsheet.js`는 선택 상자를 그대로 둡니다. 값과 옵션, `input`·`change` 이벤트는 선택 상자의 것이고 고른 옵션도 선택 상자가 보여 주므로, 기능 스크립트와 요청 조립은 고칠 것이 없습니다. 바뀌는 것은 누를 때 열리는 목록뿐입니다. WebView는 `mousedown`의 기본 동작으로 자기 목록을 열기 때문에 문서의 캡처 리스너가 그 기본 동작을 막고, `click`에서 시트를 엽니다. 키보드의 Enter, 스페이스, 위·아래 화살표, F4도 같습니다. 리스너가 문서에 있어서 측정 파일 대응 표처럼 나중에 만들어지는 선택 상자도 따로 연결할 필요가 없습니다. 시트의 제목은 선택 상자의 `aria-label`, `aria-labelledby`, 라벨 순으로 찾은 이름이고(끝의 쌍점은 뗍니다), 행은 옵션마다 하나입니다. 지금 고른 옵션은 탐색 막대의 현재 화면과 같은 색을 띠고 체크 표시가 붙으며, 목록이 길면 그 옵션이 가운데 오도록 스크롤해 엽니다. 옵션을 누르면 선택 상자의 값을 바꾸고 `input`과 `change`를 보낸 뒤 닫힙니다. 같은 옵션을 다시 누르면 아무 이벤트도 보내지 않습니다. 시트 바깥, Escape, 뒤로 가기는 고르지 않고 닫습니다. 꺼진 선택 상자는 시트를 열지 않고, 꺼진 옵션의 행은 누를 수 없습니다. 새 선택 상자를 넣을 때는 라벨만 붙이면 됩니다.

휴대폰 화면에는 보기만 하고 아무것도 할 수 없는 항목을 두지 않습니다. 그래서 설정 화면에는 데스크톱의 폴더 묶음(데이터 폴더와 설정 파일 경로)이 없습니다. 둘 다 앱 전용 저장 공간이라 사람이 열 수도 바꿀 수도 없습니다. 정보 화면의 소개에는 이름만 크게 두고, 버전은 시스템 정보 목록의 첫 줄에 있습니다. 부제는 `app_subtitle_android`입니다(앱은 측정하지 않으므로 데스크톱 부제의 '측정'을 뺐습니다).

BRIR 작업을 시작하면 작업 시트가 화면 전체로 열려 진행 막대, 단계 목록, 접힌 작업 기록, 취소 버튼을 보여 줍니다. 시트를 내려도 작업은 계속되고, 동작 버튼 위의 가는 막대가 진행 중인 단계를 보여 주며 누르면 시트가 다시 열립니다. 작업이 끝나면 시트에 출력 폴더 경로, 정렬 보고서, 실패 문장이 남습니다. 출력 폴더 열기가 실패하면 오류 대신 폴더 경로를 알려 줍니다. 출력 복원은 시트 없이 자기 화면의 결과 카드에서 보여 줍니다.

뒤로 가기는 맨 위의 것부터 닫습니다. 선택 시트, 설명 시트, 확인 대화상자(취소로 답함), 고르기 시트, 업데이트 대화상자, 작업 시트(내림)를 차례로 닫고, 다른 화면에 있으면 처리 화면으로 돌아갑니다. 닫을 것이 없으면 `handleBack()`이 false를 돌려주고 시스템이 앱을 떠납니다. 처리기가 등록되어 있는 동안에는 시스템의 뒤로 가기가 동작하지 않으므로, 돌아갈 것이 있을 때만 등록합니다. 작업이 도는 동안에는 앱을 떠나지 않습니다. 안드로이드는 액티비티와 함께 프로세스를 끝내므로 떠나면 작업이 사라지기 때문입니다. 이때는 위의 것들을 닫은 다음 작업 시트를 다시 열어 보여 주고, 출력 복원이면 그 화면으로 갑니다. 작업이 끝나면 평소 순서로 돌아갑니다.

안드로이드 화면이 쓰는 키도 데스크톱과 같이 `ui_catalog.rs`가 모든 언어에서 확인합니다. `android.html`의 `data-i18n`, 아이콘 버튼 이름의 `data-i18n-label`, 업데이트 대기 문구의 `data-pending-key`를 읽습니다. 화면에 보이는 문구는 이모지 없이 씁니다. 그래서 업데이트 대화상자는 2.x 키 대신 `update_new_version`, `update_button_skip_version`, `update_button_later`를 씁니다.

## 검증과 갤러리

저장소 루트에서 실행합니다. 모든 명령은 포그라운드로 실행합니다.

```powershell
npm --prefix apps/impulcifer-app run typecheck
npm --prefix apps/impulcifer-app run test:contracts
cargo test -p impulcifer-service --lib settings
cargo test -p impulcifer-service --test ui_catalog
cargo test -p impulcifer-policy -- app_scripts_opt_into_type_checking
cargo test -p impulcifer-app --test smoke
py -3.14 apps/impulcifer-app/tests/ui_gallery.py --out target/ui-gallery
```

갤러리는 설치된 Playwright Chromium으로 모의 IPC 응답을 주입합니다. 실제 앱, 장치 녹음, 업데이트 실행은 하지 않습니다. 데스크톱 시나리오는 초기 스크립트 하나를 쓰고, 안드로이드 시나리오는 그 위에 안드로이드 응답을 담은 스크립트 하나를 더 씁니다. 페이지·콘솔·리소스 오류가 있거나 PNG 수가 270장(데스크톱 224장, 안드로이드 46장)과 다르면 실패합니다.

데스크톱(1280 px 너비)

- 두 스킨 × 두 테마 × 영어·한국어 × 설정·정보·녹음 화면 24장
- Studio의 처리 후 정렬 보고서 × 두 테마 × 두 언어 4장
- Studio 복원의 다섯 계획 상태와 실행 성공 × 두 테마 × 두 언어 24장
- 녹음 모드 비활성화·고정 모드 거부 × 두 스킨 × 두 테마 × 두 언어 16장
- 녹음의 22.2 채널 표 8장, HDMI 채널 순서와 확인 창 16장, 출력 채널 부족 8장
- 사용자 EQ 두 경우 × 두 스킨 × 두 테마 × 두 언어 16장
- Studio 고급 옵션 다섯 장면 × 두 테마 × 두 언어 20장

- 룸·BRIR·헤드폰 측정 파일(REW, Dirac Live) × 두 스킨 × 두 테마 × 두 언어 각 16장

안드로이드(412×915 CSS px, 2배 배율, 터치), 파일 이름은 `android-<장면>-<언어>-<테마>.png`

- 처리 화면, 모든 그룹을 연 처리 화면, 출력 복원 준비, 설정, 정보 × 두 테마 × 두 언어 20장

추가 동작 검사에서는 300ms 지연 호출, 오래된 응답 무시, 옵션 변경 후 재확인, Stable에서 계획 미호출, 설정 부모 폴더 열기, 언어 변경, 녹음 확인의 자리표시자, 접근 모드 성공·오류 표시를 확인합니다. 안드로이드 검사(`android_checks`)는 맨 먼저 돕니다. P63의 열아홉 가지 상태에서 Studio와 안드로이드가 같은 BRIR 요청을 보내는지, Studio의 요청 조립이 읽는 모든 ID가 `android.html`에 있는지 봅니다. 그리고 저장소 안내와 `visibilitychange`, 고르기 시트의 이동·선택·상태, 뒤로 가기의 순서와 처리기 등록, 작업 중의 뒤로 가기, 선택 시트(아래 문단), 작업 시트의 시작부터 결과까지, 실패 문장, 폴더 열기 실패, 출력 복원의 다섯 상태와 실행, APK 업데이트, 아홉 언어에서 화면에 남은 키가 없는지, 360 px 너비에서 가로 스크롤이 없고 보이는 조작 요소가 모두 48 px 이상인지 확인합니다. 하나라도 어긋나면 무엇이 어긋났는지 적은 문장으로 실패합니다. 실제 앱 검사는 `docs/rust/APP-SMOKE.md`를 따릅니다.

선택 시트 검사(`android_option_sheet_checks`)는 선택 상자를 실제 터치로 누릅니다. 브라우저 자체의 목록은 시트가 초점을 가져가면 저절로 닫히므로, 나중에 확인하면 열렸던 것을 놓칩니다. 그래서 손가락이 선택 상자 위에 있는 동안(`mouseup`, `click`, `keyup`)의 `:open` 상태를 기록해 한 번도 열리지 않았는지 봅니다. 기본 동작을 막는 줄을 지운 판은 이 검사에서 실패합니다. 그 밖에 제목과 행이 선택 상자의 라벨·옵션과 같은지, 고른 값과 이벤트(한 번씩), 같은 옵션을 다시 누를 때, 바깥 터치·뒤로 가기·Escape, 키보드로 열고 고르기, 꺼진 선택 상자와 옵션, 나중에 만들어진 측정 표의 선택 상자, 긴 목록의 스크롤을 확인합니다. 페이지의 모든 선택 상자는 아홉 언어, 360 px 너비에서 제목이 있고 행이 옵션과 같으며 시트보다 넓지 않고 행이 48 px 이상인지 봅니다. 에뮬레이터 시험(`DemoProcessingTest`)도 설정 화면의 언어 선택 상자를 실제 터치로 눌러 같은 것을 실제 WebView에서 확인하고, 시트에서 다른 언어를 골라 화면이 바뀌는지 봅니다.
